# Claw & Order logic, security and operations audit

Date: 2026-11-03. Scope: backend/scoring, roster identity and lifecycle, Discord role reconciliation, invitation email, dashboard ingestion/persistence, operator CLI, human approval, agent instructions and deployment examples. Baseline commits were backend `a4c9a42ba929e490130b9feb449e074d9616431a` and dashboard `36a96b5dddda85b72cd4ad9532e312d69e35f512`. This is an implementation-team audit with reproducible tests, not an independent review or a live Cyberlabs penetration test.

## Outcome

The review found substantive logic and operational gaps despite the earlier passing tests. The code and instructions now implement reviewed student changes, limited planner authority, readable reports, explicit completion evidence and safer recovery. Production promotion remains conditional on the school's actual role definitions, host isolation, Discord/SMTP pilot and production-sized load/restore checks.

## Verification method and evidence

- Manual source and failure-path review, followed by targeted regressions for each corrected boundary. Existing scoring/reporter/webhook reliability tests remain in the suite.
- Full backend/reporter/enrollment pytest suite and dashboard tests, ESLint and production build. Existing CI repeats tests on Python 3.12 and Node 20. Proposed advisory gates are included as patches; they are not active until an owner applies them with workflow authorization.
- `pip-audit 2.10.1`, `npm audit` for both full and production graphs, and `bandit 1.9.4`. Advisory counts are a point-in-time registry result, not proof of general security.
- Isolated PostgreSQL 16 with separate fresh backend and dashboard databases, repeatable migrations, real HTTP, actual planner CLI and separate human approval CLI. Two synthetic students, three class enrollments, a team transfer preserving the other class, one scoring event, no replay duplicate, no student identity export and no invented machine health.
- The rehearsal records proposed, waiting, applied, verified and history reports in [examples/](examples/README.md). Fake Discord operations and fake SMTP tests are explicitly distinguished from real server/email delivery.
- Container build/smoke as an unprivileged user, excluded private files, archive checksums and source commit references in the handoff manifest.

See `enrollment-validation.json` for the current recorded counts and `audit-evidence.json` for scanner summaries. Reproduce with `python -m pytest tests -q`, dashboard `npm test`, `npm run lint`, `npm run build`, `npm audit --omit=dev`, `pip-audit -r requirements.lock`, and `scripts/rehearse_enrollment.py` against explicitly named fresh rehearsal databases.

## Static-scan dispositions

Bandit reports are triaged; no blanket suppression is added. Dynamic table-name SQL in startup checks uses a fixed literal tuple with no request-controlled identifier. The reporter's `0.0.0.0` is a heartbeat payload target, not a listening socket. Assertions in the normalizer are its self-test harness, not enforcement in request handling. Rehearsal subprocesses use argument arrays with no shell and operator-selected source paths. Blank bot-token constants deliberately disable live Discord in synthetic runs. The load-rehearsal URL opener now validates HTTPS/loopback origins before attaching a team token. These findings and any remaining low/medium flags are reviewed context, not an assertion that static analysis proved absence of flaws.

## Remaining risks and launch gates

A repository owner must run `git apply claw-and-order/deploy/ci-security-gate.patch` from the backend repository root and `git apply docs/ci-security-gate.patch` from the dashboard repository root, review the diffs and push with workflow authorization. The backend patch adds pinned pip-audit and a lockfile check; the dashboard patch adds a production npm audit check. Run those commands manually until the gates are activated. No credential scope was expanded from this workspace.
