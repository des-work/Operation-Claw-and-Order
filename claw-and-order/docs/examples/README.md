# Synthetic operator reports

These six reports came from the actual CLI/API and isolated PostgreSQL audit rehearsal. All student IDs and server/role IDs are synthetic; Discord behavior was replaced with a fake adapter. No real student data, registration codes or emails are included. The examples demonstrate formatting and state explanations, not a live school deployment.

1. [Initial proposal](01-roster-proposed.md): before/after roster and permission plan.
2. [Registration still waiting](02-roster-waiting.md): one unregistered student prevents a false completion claim.
3. [Targeted team move](03-team-move.json.md): one student/class changes while another class remains intact.
4. [Human approval receipt](04-team-move-applied.json.md): saved/queued is still waiting.
5. [Verified move](05-team-move-verified.md): matching role read-back and channel-access evidence from the fake adapter.
6. [Student history](06-student-history.md): request, human approval, before/after assignment and execution trail.

Real reports belong in private institutional storage, not Git. Follow HUMAN-OPERATIONS.md and retain the corresponding restricted JSON/change ticket. The message text and observed timestamps are generated by the application; report content alone does not establish independent institutional identity or tamper-proof retention.
